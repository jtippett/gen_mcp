# MCP 2025-11-25 Spec Upgrade Design

## Overview

Upgrade gen_mcp from MCP spec `2025-06-18` to `2025-11-25` with full feature parity.

## Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Scope | Full feature parity | Quality-first approach |
| Implementation order | Foundation first | Each feature builds on stable foundation |
| Tasks architecture | Separate subsystem | Clean separation, spec marks as experimental |
| Tasks storage | Configurable backend + ETS default | Matches SessionController pattern |
| OAuth | Schema-only | Users handle auth in their Phoenix app |
| Elicitation | Full support | Tools/session controllers can send ElicitRequest |

## New Features in 2025-11-25

### Major

1. **Tasks (experimental)** - Durable request tracking with polling/deferred results
2. **Icons** - Optional metadata for tools, resources, resource templates, prompts
3. **Tool calling in sampling** - `tools` and `toolChoice` in CreateMessageRequest
4. **Elicitation enhancements** - URL mode, better enums, default values
5. **OAuth improvements** - OIDC Discovery, incremental scopes, Client ID Metadata

### Minor

- `description` field in Implementation interface
- JSON Schema 2020-12 as default dialect
- Request payloads decoupled into standalone parameter schemas

### 3. Resource Subscriptions

**State:** Add `subscribed_uris: MapSet.new()` to Suite State struct.

**Handlers:**
```elixir
def handle_request(%MCP.SubscribeRequest{} = req, _channel, state) do
  uri = req.params.uri
  state = %{state | subscribed_uris: MapSet.put(state.subscribed_uris, uri)}
  {:reply, {:result, %MCP.Result{}}, state}
end

def handle_request(%MCP.UnsubscribeRequest{} = req, _channel, state) do
  uri = req.params.uri
  state = %{state | subscribed_uris: MapSet.delete(state.subscribed_uris, uri)}
  {:reply, {:result, %MCP.Result{}}, state}
end
```

**Public API:**
```elixir
@spec notify_resource_updated(session_id :: String.t(), uri :: String.t()) ::
      {:ok, :notified | :not_subscribed | :no_listener} |
      {:error, {:session_not_found, String.t()}}
def notify_resource_updated(session_id, uri)
```

**Capabilities:** Advertise `resources: %{subscribe: true}` when resources available.

### 4. Sampling Enhancements

Auto-generated from schema. New fields in CreateMessageRequest:
- `tools` - list of Tool definitions
- `toolChoice` - controls tool selection (`auto`, `none`, specific)

New content types:
- `ToolUseContent` - model requests tool use
- `ToolResultContent` - result of tool execution

Existing sampling flow passes through without code changes.

### 5. Elicitation Support

**API:**
```elixir
@spec elicit(channel :: Channel.t(), params :: map()) ::
      {:ok, ElicitResult.t()} | {:error, term()}
def elicit(channel, params)
```

**Example usage:**
```elixir
def call(_params, channel, _context) do
  case GenMCP.Suite.elicit(channel, %{
    message: "Please enter your API key",
    requestedSchema: %{
      type: "object",
      properties: %{api_key: %{type: "string", title: "API Key"}},
      required: ["api_key"]
    }
  }) do
    {:ok, %{action: "accept", content: content}} -> # Use input
    {:ok, %{action: "decline"}} -> {:error, "User declined"}
    {:error, reason} -> {:error, reason}
  end
end
```

**URL mode:**
```elixir
GenMCP.Suite.elicit(channel, %{
  message: "Please authenticate",
  requestedSchema: %{
    type: "url",
    url: "https://auth.example.com/oauth?state=...",
    description: "Click to authenticate"
  }
})
```

**Implementation:**
- Verify client supports elicitation before sending
- Handle timeout/cancellation
- Return error if client doesn't support elicitation

### 6. Tasks (Experimental)

#### TaskStore Behaviour

```elixir
defmodule GenMCP.Suite.TaskStore do
  @type task_id :: String.t()
  @type task :: %{
    id: task_id(),
    status: :pending | :running | :completed | :failed | :cancelled,
    result: term() | nil,
    error: term() | nil,
    metadata: map(),
    created_at: DateTime.t(),
    updated_at: DateTime.t()
  }

  @callback init(opts :: keyword()) :: {:ok, state :: term()}
  @callback create(task_id, metadata :: map(), state) :: {:ok, task, state} | {:error, term()}
  @callback get(task_id, state) :: {:ok, task, state} | {:error, :not_found}
  @callback update(task_id, updates :: map(), state) :: {:ok, task, state} | {:error, term()}
  @callback delete(task_id, state) :: {:ok, state} | {:error, term()}
  @callback list(session_id :: String.t(), state) :: {:ok, [task], state}
end
```

#### Default ETS Implementation

```elixir
defmodule GenMCP.Suite.TaskStore.ETS do
  @behaviour GenMCP.Suite.TaskStore
  # ETS table per MCP server instance
  # Tasks keyed by {session_id, task_id}
  # Configurable TTL with periodic cleanup
end
```

#### Configuration

```elixir
use GenMCP.Suite,
  task_store: {GenMCP.Suite.TaskStore.ETS, ttl: :timer.hours(1)}

# Or custom
use GenMCP.Suite,
  task_store: {MyApp.RedisTaskStore, connection: :redis_pool}
```

#### Request Handlers

- `tasks/get` - Get task status/result
- `tasks/cancel` - Cancel a running task
- `tasks/list` - List tasks for session

#### Public API

```elixir
@spec complete_task(session_id, task_id, {:ok, result} | {:error, error}) ::
      :ok | {:error, term()}
def complete_task(session_id, task_id, outcome)
```

#### Notifications

Send `notifications/tasks/status` when task status changes.

#### Capabilities

```elixir
%{tasks: %{supported: true}}
```

## Testing Strategy

**Unit tests:**
- All existing tests pass with new entities
- Icon fields included in list responses
- Subscribe/unsubscribe handlers, notification logic
- CreateMessageRequest with tools/toolChoice
- elicit/2 function, capability checks, URL mode
- TaskStore behaviour, ETS implementation, request handlers

**Integration tests:**
- Full subscription flow: initialize → subscribe → trigger → verify SSE
- Full task flow: initialize → start task → poll → complete → get result
- Full elicitation flow: initialize → elicit → receive response
- Sampling with tools round-trip

**Backwards compatibility:**
- Test against 2025-06-18 clients
- Graceful degradation when client doesn't support new features
